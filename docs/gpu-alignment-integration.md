# Portable GPU English coarse alignment

The production `CoarseAlignment(directory)` now uses its configured model directory. It has no dependency on a Codex task, evaluation receipt, externally supplied transcript, or prototype folder. Cohere remains the only transcript authority. This replaces the absolute-path research adapter described in the earlier research handoff.

## Model preparation and inference

The existing optional download remains pinned to the original 365,352,120-byte ONNX model, token vocabulary and licenses in `ALIGNMENT_SPEC`. That file is **source model data**, not the inference backend. No new model repository or download is introduced. Setup prepares its data locally, and existing verified downloads are reused without another network request. Older caches with only the original files can also be prepared by the normal provider loader on first use.

`alignment_model.prepare_model(directory)` verifies the entire original model and token digests before using the committed 714-initializer byte map. It applies the same 422 tensor transforms as the measured converter, checks each converted tensor digest/shape/dtype, and writes a deterministic float32 archive. Output is published atomically under `directory/mlx-f32-v1-38ff6a225e75/weights.npz`, protected by a cross-process preparation lock. Failed conversion leaves no usable partial model. An existing prepared artifact with a changed digest is refused. Preparation uses NumPy and standard file operations; it creates no ONNX session, performs no neural inference and downloads nothing.

The converted archive is **1,302,120,358 bytes**, SHA256 `38ff6a225e75caa6e19c35a9b5823015e2550451bd0a394a10f6cda87f42058d`. Required local storage includes the original source plus this archive, with a 64 MiB write reserve during conversion. It preserves representable cached UINT8 weights after dequantization; it does not recover the original unquantized checkpoint and removes dynamic activation quantization. The model remains Apache-2.0 licensed and the reused MLX Audio forward components MIT licensed. Existing package/model notices remain included.

`mlx_ctc_forward.load_gpu_model` requires Metal and explicitly selects/checks the GPU default and stream. It checks the exact tested runtime and forward-source digests before instantiating the network, loads every expected float32 tensor strictly, evaluates parameters on GPU, and has no alternate neural backend. Each forward refuses missing Metal or a CPU default/stream, performs the unchanged waveform normalization/model/log-softmax on GPU, then evaluates and synchronizes scores before emitting execution provenance. CPU-only bookkeeping and supplied-text CTC sequence alignment are separate from neural inference.

## Packaged compatibility and artifact provenance

The frozen package contains `alignment_model`, `mlx_ctc_forward`, MMS/Wav2Vec2 modules, the tensor manifest and MLX Metal distribution metadata/kernels. The tested requirements are MLX and mlx-metal **0.32.2**, MLX Audio **0.5.7** from the existing pinned Git revision, NumPy **2.5.3**, and compiled non-neural ctc-segmentation **1.7.4**. MMS and Wav2Vec2 source hashes are pinned in the manifest; matching version strings alone are insufficient. No new ONNX parser dependency is required. The older ORT package may still be bundled for legacy tooling, but this provider never imports it or creates a session.

Actual alignment results record the original source-model digest, converted model digest, conversion-manifest digest, candidate calibration identity, original PCM/text hashes and absolute anchor. GPU backend/device/stream/evaluated-score provenance is added only after completed forward evaluation. Missing execution evidence cannot enter the alignment cache or be published. Existing exact raw-evidence cache limits, language validation, admission/ownership and current revision/CAS/human-edit rules remain intact. Historical CPU and current GPU artifact identities stay distinct; existing saved historical documents remain readable.

The frame/score identity is `ami-english-coarse-mlx-f32-v1-5ab4e661e62f-38ff6a225e75`, the unchanged 320-sample emission-cell clock, score floor −20 and 250 ms conservative ownership margin. Frozen independent English AMI checks passed 42/42 held-out associations, 30 ms median / 188.5 ms combined-endpoint p95, with no threshold/offset fitting. End-only p95 remains 397.5 ms. These external forced-aligned reference times support bounded coarse highlighting/seeking/ownership, not exact phonetic trimming or broad language claims.

The previously measured same-network 30-second GPU Engine replay took 18.818 s versus historical 41.666 s, preserving all 33 publication semantics, all twelve same-source GPU artifacts and the original eight-word tail under Speaker 1. That timing measurement preceded this portability/provenance patch; no new acoustic speed or native package qualification is claimed by source tests. The forward math, model weights, configuration, vocabulary and score/frame policy remain unchanged. Portable loader/data-preparation validation is recorded separately in the integration handoff.

## Remaining acceptance

Source tests cover conversion values/identity, corruption and atomicity, exact cache reuse, backend refusal, packaged imports/data, provenance and optional setup without redownload. A signed frozen package still needs actual loader/import verification and normal acoustic/native acceptance before release. Do not run a package builder or change release/app state as part of applying this source patch.

Voice embeddings are a separate qualification: Core ML `ALL` permits CPU and does not prove GPU/ANE execution. The integrator still needs strict backend/device policy and actual embedding execution/placement evidence, then voice calibration/recognition checks. This CTC patch neither changes nor qualifies voice inference. CTC final-phase weight release remains a separate proposed memory optimization; it is not included and does not block this port.
