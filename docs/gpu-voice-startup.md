# Qualified GPU voice startup and ownership

Ordinary configuration startup, managed setup activation and managed-cache discovery use `voice_gpu_runtime.load_approved_runtime`. It verifies the source-owned candidate config, unchanged qualification/checkpoint bytes, artifact inventory, scoring contract, three neural/waveform modules and inference wrapper before returning a lazy backend. Startup performs no neural initialization or prediction. The first permitted passage request starts one registered, offline inference child, and subsequent enrollment/background calls reuse it.

`voice_gpu_calibration.json` is a separate accepted source-candidate config for the bounded natural functional evidence. It preserves the exact model identity, threshold 0.5827445050278138, margin 0.22375670158951808 and two-clip minimum. The sealed development checkpoint is copied unchanged, including its unapproved flag. The qualification receipt remains unchanged, including its historical no-production-activation fields. Creating this source candidate does not install, activate or publish an app. This small public English AMI scenario/headset evidence does not establish population false-accept rates, other languages/capture routes, base-training exclusion or legacy ALL numerical compatibility.

The parent proxy acquires runtime activity admission before dispatch, serializes requests and checks response identity, sequence, completed declarations, unit vectors and a stable inference owner. It preserves the already normalized vector values. Both model construction and embedding run through the frozen `ThreadBoundVoiceBackend` in the child. Metal execution and a 256 MiB MLX bound are enforced by the unchanged adapter. The worker uses the existing Mac memory-pressure check and bounded 90-second requests; it has no CPU/CoreML neural fallback, network access, model download or automatic inference retry. Framing and diagnostics are bounded, and failure closes/reaps the child rather than retrying a query.

The child is registered through the pipeline's existing shutdown lock and owns a separate process group. A voice-specific adapter preserves the pipeline source and its timing qualification identity. Idle residence can admit an update; queued/running requests retain `RuntimeUpdates` activity admission. The pipeline registry continues to report idle only after every child exits. Update shutdown closes the idle voice owner before checking that registry and acknowledging cleanup. Ordinary shutdown seals pipeline admission and cancels tracked voice groups before taking the app lock, including descendants that keep pipes open after a frozen launcher exits. Both paths join the proxy readers and remove only reaped children from the registry. The source entry point is `voice_gpu_worker.py`; the frozen entry point is `--voice-worker` in `packaging/sidecar.py`.

An explicit invalid config stays unavailable and cannot fall back to a cached default. Managed setup reads the same selected config, so missing/changed policy reports `runtime_unqualified`/Updates; an accepted runtime with missing weights reports `model_missing`/Models. A worker failure stays unavailable until deliberate setup retry. Installing weights does not change policy or source qualification.

Existing saved names and profile payloads remain untouched. The optional `/api/people` states are `none`, `stored_unavailable`, `unverified`, `incompatible_runtime` and `compatible`. Exact complete original model dictionaries determine compatibility. Incomplete identities are not default-filled, and ALL profiles are not converted or relabeled. Replacement requires the existing deliberate consented Remember voice action. Automatic matches remain unconfirmed and never enroll or update a profile.

The new CPU regressions use disposable state and a zero-neural IPC fixture. They cover noninjected environment startup, invalid-policy refusal, resident reuse across callers, update reservation, malformed/oversized responses, child exit/timeouts, ordinary cancellation while enrollment holds the app lock (including a pipe-holding launcher descendant), update acknowledgement after reaping, and raw profile preservation. Existing managed download/retry/restart, consent, recognition and CoreML refusal tests remain applicable. Real acoustic results are reused; these regressions do not repeat or replace them.
